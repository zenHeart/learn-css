2px line-height 空行问题 — 行内格式化上下文详解

问题现象

当 line-height 设置为很小的值（如 2px）而 font-size 保持正常（如 16px）时， 文本会「溢出」行框，产生看似「空行」的效果。奇怪的是，给父元素或子元素设置一个很小的 font-size 就能解决这个问题。

核心矛盾：line-height 控制行框的高度，但实际渲染高度还受 font-size 决定的内容区影响
核心概念：行框（Line Box）模型
// 行内格式化上下文（Inline Formatting Context）

行框 Line Box
内容区（由 font-size:16px 决定）
↑ 溢出！

// 当 line-height < font-size 时
• 内容区高度 ≈ font-size（16px）
• 行框高度 = line-height（2px）
• 16px > 2px → 内容溢出行框 → 「空行」

关键概念区分

概念决定因素作用
内容区（Content Area） font-size + line-height 的计算 文本实际占据的高度，基于 em box
行内盒（Inline Box） line-height 包裹内容区的盒子，影响 line box 高度
行框（Line Box） 子行内盒的最高点～最低点 真正决定换行和布局的高度

为什么子元素设 font-size 能解决？
// 原理：行内盒的高度由 line-height 决定 // 但行内盒的「内容区」由自身 font-size 决定 // 子元素 span 设置 font-size: 1px .child { font-size: 1px; // ← 内容区缩小到 1px line-height: 2px; // 行内盒 2px，包裹 1px 内容区 } // 结果：2px 行内盒包裹 1px 内容区 → 不溢出 // 但文字会非常小看不清！
这种「解决」其实是视觉欺骗 — 文字缩小到看不清。正确做法是确保 line-height ≥ font-size
为什么父元素设 font-size 能解决？
// 原理：line-height 的 number 值是相对于父元素 font-size 的倍数 // 父元素设置 font-size: 2px; line-height: 1 .parent { font-size: 2px; // ← 基准变成 2px line-height: 1; // 1 × 2px = 2px（实际 line-height） } // 子元素继承时的 computed value： // line-height: 1 → computed: 2px // 子元素自己的 font-size 如果是 16px... // 关键：子元素 font-size 不继承，是独立值 // 但 line-height 如果是 normal/number，会重新计算
line-height 的继承机制：
• line-height: normal → 继承时重新计算（基于子元素 font-size）
• line-height: 数值（如 1.5）→ 继承的是倍数值，子元素乘以自己的 font-size
• line-height: 固定值（如 16px）→ 直接继承，不变
正确做法
场景正确写法说明
需要紧凑行高 line-height: 1.2（倍数） 相对于 font-size 自动计算，确保不小于 font-size
图标 + 文字对齐 line-height: 0 + vertical-align: middle 消除行框对图标高度的影响
按钮/标签 line-height 等于容器高度 单行文字垂直居中
多行文字 line-height 推荐 1.5～1.8 可读性最佳的行高
核心要点
公式：行框高度 = 子行内盒的「最高点～最低点」

当 line-height < font-size 时：
• 内容区高度 ≈ font-size
• 行内盒高度 = line-height
• line-height < font-size → 内容溢出 → 「空行」视觉

「解决」的本质：
• 子元素 font-size: 1px → 缩小内容区，但文字看不清
• 父元素 font-size: 2px → line-height: 1 计算基准变成 2px

正确做法：line-height ≥ font-size，或使用倍数（1.2/1.5 等）
