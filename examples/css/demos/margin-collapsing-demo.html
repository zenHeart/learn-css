CSS Margin Collapsing & BFC

外边距合并机制与 Block Formatting Context 原理 — 交互式演示

场景一：兄弟元素之间的 margin 合并

上元素 (margin-bottom: 20px)
下元素 (margin-top: 30px)
/* 结果：两个元素的 margin 合并为 max(20px, 30px) = 30px */ .box1 { margin-bottom: 20px; } .box2 { margin-top: 30px; } /* 实际间距 = 30px（取较大值），而不是 50px */
核心结论：垂直方向相邻的 margin 会合并，取较大值。 这是 CSS 的默认行为，目的是让段落之间的间距一致（不管内容多少）。

场景二：父元素与第一个/最后一个子元素的 margin 合并

问题：为什么子元素的 margin 似乎"穿透"到父元素外面？

子元素 (margin-top: 40px)
/* 现象：子元素的 margin-top 没有把父元素撑开， 而是"穿透"到父元素外面，和父元素的 margin-top 合并 */ .parent { margin-top: 0; } .child { margin-top: 40px; } /* 实际：整个父容器距离顶部的距离是 40px，而不是 0 */
为什么发生？当父元素没有 border、padding、inline content 阻挡时， 父元素的 margin-top 和第一个子元素的 margin-top 会合并（形成一个更大的 margin）。 这是因为它们共享同一个"块级上下文边缘"。

场景三：空块级元素的上下 margin 合并

上面的元素
空元素 (margin-top:30px + margin-bottom:30px)
下面的元素
/* 空元素的上下 margin 也会合并 */ .empty { margin-top: 30px; margin-bottom: 30px; } /* 实际效果 = max(30px, 30px) = 30px，不是 60px */ /* 如果空元素有 border 或 padding，则不会合并 */ .empty { margin-top: 30px; margin-bottom: 30px; padding: 1px 0; } /* 不合并 */
根因：空元素的上下 margin "相遇"了，合并为一个。 加上任何 border、padding、height、min-height 都可以阻止合并。

BFC 如何阻止 margin 合并？

BFC（Block Formatting Context）创建一个独立的格式化上下文， 其内部的 margin 不会与外部的 margin 合并。

❌ 无 BFC（默认）— margin 穿透

子 margin-top: 40px
/* margin 穿透到父元素外部 */

✅ overflow: hidden — 创建 BFC

子 margin-top: 40px
/* margin 被"包含"在父元素内 */

所有触发 BFC 的方式

overflow: hidden/scroll/auto display: flow-root display: inline-block position: absolute/fixed float: left/right flex/grid 容器
/* overflow: hidden 创建 BFC */ .parent { overflow: hidden; } /* 或更现代的方式 */ .parent { display: flow-root; } /* 唯一作用就是创建 BFC */

总结：overflow: hidden 阻止 margin 合并的本质是创建了 BFC。 BFC 内部的布局与外部隔离，内部的 margin 不会"穿透"到外部与外部的 margin 合并。 这就是为什么 overflow: hidden 可以"包含"子元素的 margin。
