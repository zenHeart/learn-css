OKLCH 颜色插值对比

核心问题：RGB/HSL 插值的缺陷

在 RGB 和 HSL 颜色空间中，数值的变化与人眼感知不完全对应。
这导致颜色插值（渐变、动画）时会出现不自然的中间色。

RGB 插值（❌ 不推荐）

linear-gradient(to right,
  rgb(255 0 0), rgb(0 0 255))

⚠️ 中间色经过紫色调，路径不可预测

HSL 插值（⚠️ 有问题）

linear-gradient(to right,
  hsl(0 100% 50%), hsl(240 100% 50%))

⚠️ 中间色变得灰暗（灰度陷阱）

OKLCH 插值（✅ 推荐）

linear-gradient(to right,
  oklch(55% 0.25 25), oklch(45% 0.25 265))

✅ 路径平滑，色彩饱满，视觉一致

灰度陷阱（HSL Gray Hole）

HSL 插值时，颜色容易经过低饱和度的灰色区域，造成"褪色"效果。
这是因为 HSL 的 S（饱和度）不是基于感知均匀的模型。

红 → 绿 插值对比

HSL：中间色明显变暗变灰

OKLCH：色彩饱满过渡均匀

动画中的颜色过渡

OKLCH 的感知均匀性让它成为 CSS 动画中颜色过渡的最佳选择。
无论是 hue 旋转、色阶切换还是主题动画，都应该使用 OKLCH。

Hue 旋转动画对比

OKLCH：色相平滑旋转（0° → 360°）

饱和度脉动

OKLCH：C 值 0.1 → 0.3 脉动，饱和度变化均匀

彩虹渐变

background: linear-gradient(to right,
  oklch(60% 0.22 0), /* 红 0° */
  oklch(60% 0.22 60), /* 黄 60° */
  oklch(60% 0.22 120), /* 绿 120° */
  oklch(60% 0.22 180), /* 青 180° */
  oklch(60% 0.22 240), /* 蓝 240° */
  oklch(60% 0.22 300), /* 品红 300° */
  oklch(60% 0.22 360)); /* 红 360° */
