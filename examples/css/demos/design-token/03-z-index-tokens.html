📊 Z-Index Tokens - 层级令牌

来自 Martin Fowler 文章的实践案例：解决 z-index 魔法数字问题

问题：魔法数字的困境

在微前端架构中，不同团队可能使用任意的 z-index 值，导致层级冲突：

/* ❌ 魔法数字 - 难以维护 */ .modal { z-index: 9999; } .dropdown { z-index: 1000; } .tooltip { z-index: 8888; }

解决方案：Z-Index Token 标尺

使用命名的 Token 值，清晰表达每个层级的语义和用途：

/* ✅ 语义化 Token - 团队协作友好 */ "z-index": { "$type": "number", "default": { "$value": 1 }, "sticky": { "$value": 100 }, "navigation": { "$value": 200 }, "spinner": { "$value": 300 }, "toast": { "$value": 400 }, "modal": { "$value": 500 }, "tooltip": { "$value": 600 } }

Token 对照表

Token Value Use Case
--z-index-default 1 默认元素，正常文档流
--z-index-sticky 100 position: sticky 元素
--z-index-navigation 200 导航栏、顶部菜单
--z-index-spinner 300 加载指示器
--z-index-toast 400 Toast 通知
--z-index-modal 500 模态框、对话框
--z-index-tooltip 600 Tooltip、Popover

优势总结

  • 避免冲突：不同团队使用统一标尺，不会出现 999 vs 1000 的困惑
  • 语义清晰：名称即含义，开发者无需猜测数值大小
  • 易于扩展：新增层级时按需插入，保持间隔便于未来扩展
  • 跨团队协作：微前端场景下，各团队引用相同 Token 规范
