CSS 层叠上下文调试交互演示

什么是层叠上下文（Stacking Context）

层叠上下文是 HTML 元素在三维空间中按 z 轴顺序层叠的概念。当元素创建新的层叠上下文时，其子元素的 z-index 只在该上下文内部有效。

创建层叠上下文的条件

条件 示例
根元素 <html>
position + z-index position: relative; z-index: 1
opacity < 1 opacity: 0.9
transform transform: translateZ(0)
filter filter: blur(1px)
backdrop-filter backdrop-filter: blur(10px)
CSS Grid/Flex + z-index display: flex; z-index: 1

关键概念

z-index 是相对的！
子元素的 z-index 值只在创建它的层叠上下文内部有意义。 不同层叠上下文之间的比较只看它们"根"的 z-index 值。

核心规则

1. 层叠上下文 A 内的元素，永远无法超过层叠上下文 A 的边界
2. 不同层叠上下文之间，根 z-index 大的优先
3. 同一层叠上下文内，按 z-index 从低到高排序

场景1：正常 z-index 层叠

没有层叠上下文干扰时，z-index 直接决定元素的层叠顺序。数值越大，越在上层。

交互演示

z-index: 1
z-index: 2
z-index: 3
/* 正常层叠：z-index 决定一切 */ .box-1 { position: absolute; z-index: 1; } .box-2 { position: absolute; z-index: 2; } .box-3 { position: absolute; z-index: 3; } /* 结果：box-3 盖住 box-2，box-2 盖住 box-1 */

要点

当所有元素都在同一个层叠上下文（根层叠上下文）中时，z-index 值直接比较，值大的在上。

场景2：transform 创建层叠上下文陷阱

当父元素使用 transform 时，会创建新的层叠上下文。子元素的 z-index 只在该上下文内有效！

问题演示

紫色容器有 transform，红色方块 z-index: 1000 在它内部。
绿色方块 z-index: 2 在外部，但仍然盖住红色方块！

z-index: 1000
z-index: 2
z-index: 2
/* 父元素没有 transform - 正常行为 */ .parent { position: relative; } .child { position: absolute; z-index: 1000; } .external { position: relative; z-index: 2; } /* 问题：.child 会被 .external 盖住！ */ /* 原因：.parent 的 transform 创建了新层叠上下文 */ .parent { transform: scale(1); }

为什么 z-index: 1000 输了？

因为 .parent 有 transform，它创建了一个新的层叠上下文。

在这个新上下文中，.child 的 z-index: 1000 是相对于 .parent 的。

而 .parent 本身的 z-index 是 auto（相当于 0），所以 .parent 整体会排在 .external（z-index: 2）下面。

解决方案

1. 移除不必要的 transform
2. 将需要比较的元素放到同一个层叠上下文中
3. 给父元素设置更高的 z-index

场景3：多个层叠上下文叠加

展示多个层叠上下文同时存在时的层叠规则。

三层嵌套的层叠上下文

Context A
z-index: 1
inner: 999
Context B
z-index: 2
inner: 1
Context C
z-index: 3
inner: 1
/* 每个容器都有自己的层叠上下文 */ .context-a { position: absolute; z-index: 1; transform: scale(1); } .context-b { position: absolute; z-index: 2; transform: scale(1); } .context-c { position: absolute; z-index: 3; transform: scale(1); } /* 即使 inner 在 context-a 内有 z-index: 999 */ /* 它的层级仍然受限于 context-a 的根 z-index: 1 */ /* 所以它永远在 context-b（根 z-index: 2）之下 */

层叠上下文之间的比较规则

比较两个层叠上下文时，只比较它们"根"的 z-index。

context-a.inner (z-index: 999) vs context-b (z-index: 2)
→ 比较的是 context-a 的根 (auto=0) 和 context-b 的根 (2)
→ 0 < 2，所以 context-b 整体在上层

Chrome DevTools 调试技巧

1. 打开 Layers 面板

使用快捷键 Cmd+Shift+P（Mac）或 Ctrl+Shift+P（Windows）打开命令面板，输入 "Layers"。

2. 显示图层边框

在命令面板中输入 "Show Layer Borders"，页面上的每个图层会显示彩色边框：

  • 橙色边框：合成图层（Compositor Layer）
  • 蓝色边框：GCD 纹理图层

3. Elements 面板检查

在 Elements 面板中选中元素，查看 Styles 面板：

检查这些属性：*/ position: relative | absolute | fixed z-index: 数字 | auto transform: 非 none 值会创建层叠上下文 opacity: < 1 会创建层叠上下文 filter: 非 none 值会创建层叠上下文

4. 调试步骤流程

步骤 1：定位问题元素

使用选择工具点击被遮挡的元素

步骤 2：检查 z-index

在 Styles 面板查看 z-index 值

步骤 3：检查父元素

向上遍历，检查是否有 transform/filter/opacity/position+z-index

步骤 4：验证 Layers 面板

在 Layers 面板中查看图层顺序是否正确

常见踩坑点

1. transform 导致层叠上下文
给元素添加 transform（如 translateZ(0) 做 GPU 加速）会隐式创建层叠上下文。

2. z-index 的相对性
z-index: 100 在层叠上下文 A 内，可能比 z-index: 1 在层叠上下文 B 内更低。

3. opacity < 1 也会创建
opacity: 0.99 看起来和不透明一样，但会创建新的层叠上下文！
